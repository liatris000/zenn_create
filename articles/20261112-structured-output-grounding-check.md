## 構成案

### 1. リード: 形式検査は通るのに、値が原文と違う

構造化出力の形式保証は「形」の保証で「中身」の保証ではない、という一次情報を引いて問題を置く。
原文から項目を抜き出させたとき、スキーマ検証は全件通るのに、原文に書かれていない値が混ざる場面を最初に見せる。

### 2. 比べるもの

- A: スキーマ検証だけ（型・必須項目・enum）
- B: A + 原文照合（抜き出した値が原文に実在するか、正規化して突き合わせる）
- C: B + 項目間の整合（日付の前後関係、金額の合計など）

### 3. 検証手順

原文と、意図的に誤りを混ぜた出力のペアを用意し、A / B / C がそれぞれ何を通し何を弾くかを数える。
検査器は Python 標準ライブラリだけで書く。API キー不要で再現できる形にする。

### 4. 結果と考察

Day 2 で実測した件数だけを書く。照合で拾えないもの（原文にあるが別の箇所の値、言い換え）も正直に挙げる。

### 5. データアナリスト視点

抽出結果を集計に流す前の検査として、参照整合性チェックやロード時の件数突合と同じ位置づけで読める、という話を 2〜3 文。
