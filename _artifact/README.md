# 増えすぎたテストから、削ってよいものを測って選ぶ

テストの削除候補を出す 3 つの基準(カバレッジの重なり・ミュータントの単独検出・失敗の履歴)を、同じテストスイートに当てて比べるサンプルです。候補どおりに実際にテストを削り、ミュータントを回し直して、検出力がどれだけ落ちたかを数えます。

- `shop/pricing.py`: 対象の料金計算(数量の上限・まとめ買い割引・クーポン・送料無料)
- `tests/`: テスト 48 本。同じ入力を別名で確かめる重複を 5 組、呼ぶだけで何も確かめないテストを 5 本、わざと混ぜています
- `prune/mutate.py`: 自作の小さなミューテーションテスト。グループ A(比較・算術演算子の置き換え)で削除候補を選び、グループ B(整数定数の +1・and/or の入れ替え・not の除去・return の値を None に)で答え合わせします
- `prune/coverage_map.py`: coverage.py の dynamic context で、テストごとに通った行を取ります
- `prune/history.py`: 失敗の履歴の代わりに、手で書いたバグ 6 件
- `prune/criteria.py`: 3 つの基準。カバレッジとミュータントは、テストを並び順に見て、担う項目を残りの別のテストがすべて担っていれば削る貪欲法です
- `prune/guard.py`: 人が決めた「残す線」(規則 7 つ・テスト 14 本)
- `prune/compare.py`: 全部を回して表を出します

## 前提

- Python 3.11
- pytest 9.2.0、coverage 7.17.2(`requirements.txt`)

## 動かし方

```bash
git clone https://github.com/liatris000/liatris-20261126-test-pruning-criteria.git
cd liatris-20261126-test-pruning-criteria
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q          # 48 passed
python -m prune.compare      # 手元で 40 秒ほど(8 並列)
```

## 期待される出力

`python -m prune.compare` の出力の抜粋です(取りこぼしたミュータントと残したテストの一覧は省いています)。

```
テスト 48 本 / ミュータント A 20 個・B 41 個
全テストで殺せた数: A 20 / B 40
失敗の履歴: バグ 6 件で、一度でも落ちたテスト 15 本

## 機械の基準だけ
| 基準 | 削った本数 | 残り | 低下 A | 低下 B |
|---|---|---|---|---|
| カバレッジの重なり | 39 | 9 | 8 | 11 |
| ミュータントの単独検出 | 38 | 10 | 0 | 7 |
| 失敗の履歴 | 33 | 15 | 9 | 18 |

残す線: 規則 7 つ・テスト 14 本

## 基準 + 残す線
| 基準 | 削った本数 | 残り | 低下 A | 低下 B |
|---|---|---|---|---|
| カバレッジの重なり | 31 | 17 | 1 | 4 |
| ミュータントの単独検出 | 31 | 17 | 0 | 2 |
| 失敗の履歴 | 24 | 24 | 1 | 4 |

--deselect で外した場合のミュータント基準の低下 A: 3
```

## 確かめていない範囲

- 対象は 60 行ほどの関数 1 ファイル、テストは 48 本だけです。大きなテストスイートでの結果や所要時間は測っていません
- 失敗の履歴は実際の CI ログではなく、手で書いたバグ 6 件です。実際の履歴なら結果は変わりえます
- ミュータントは 6 種類の書き換えだけです。mutmut などの既存ツールとは比べていません
- 貪欲法はテストの並び順に依存します。並び順を変えたときの結果は確かめていません
- グループ B のうち `code.startswith('PCT') and ... -> or` の 1 個は、全テストでも殺せていません
